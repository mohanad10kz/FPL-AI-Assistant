# FPL AI Assistant 🤖⚽

> نظام ذكاء اصطناعي (rules-based) يساعدك **أسبوعياً** في قرارات Fantasy Premier League — بدون تدخل تلقائي بحسابك الشخصي.
> يدعم الآن **متعدد الفرق** ويعمل بـ **فحص يومي تلقائي للديدلاين** — يُرسل التقرير فقط في الـ24 ساعة قبل الموعد النهائي.

> [!IMPORTANT]
> **⚠️ تنويه مهم:** هذا المشروع للتوصية والتحليل فقط. القرار النهائي دائماً لك، والنظام **لا يُعدّل حسابك** بأي شكل. لا يوجد تسجيل دخول تلقائي ولا تنفيذ تحويلات آلي.

---

## ما يفعله هذا المشروع

| الخطوة | التفاصيل |
|---|---|
| 📥 يسحب بياناتك | تشكيلة كل فريق + رصيده + تحويلاته من FPL API الرسمي |
| 🏆 يقارن بأفضل 10 | يجلب تشكيلات أفضل 10 مدراء عالمياً ويقارنها — **مرة واحدة** لجميع الفرق |
| 🏥 يتحقق من الإصابات | يجلب أحدث حالات الإصابة — **مشتركة** بين كل الفرق |
| 🧠 يحلل ويوصي | يقترح تحويلات + كابتن + توقيت Chips لكل فريق **باستقلالية تامة** |
| 📱 يُرسل لتيليجرام | تقرير منفصل لكل فريق بعنوان واضح يُميّزه |
| ⏰ يفحص الديدلاين يومياً | يُشغَّل كل يوم ويُرسل فقط لو تبقّى ≤ 24 ساعة على الديدلاين |
| 🔄 يخطط على مدى الجولات | حالة التحويلات وتاريخ الإرسال لكل فريق محفوظة بملفات منفصلة |

### 3. إعداد Telegram Bot (خطوات يدوية لمرة واحدة)

> [!NOTE]
> هذه الخطوات ضرورية مرة واحدة فقط. لا تحتاج إلى أي اشتراك مدفوع.

**الخطوة 1:** افتح تيليجرام وابحث عن `@BotFather`

**الخطوة 2:** أرسل `/newbot` واتبع التعليمات:
- أدخل اسماً للبوت (مثال: "FPL Assistant")
- أدخل username ينتهي بـ `bot` (مثال: `my_fpl_assistant_bot`)

**الخطوة 3:** BotFather سيُعطيك `TELEGRAM_BOT_TOKEN` بهذا الشكل:
```
123456789:ABCDEFabcdef1234567890_XXXXXXXX
```

**الخطوة 4:** ابحث عن البوت الجديد في تيليجرام وأرسل له أي رسالة (مثال: `hi`)

**الخطوة 5:** افتح هذا الرابط في المتصفح (استبدل TOKEN):
```
https://api.telegram.org/bot<TOKEN>/getUpdates
```

ابحث عن `"chat"` → `"id"` في الرد — هذا هو `TELEGRAM_CHAT_ID`

> [!TIP]
> إذا كان `chat_id` رقماً سالباً (مثال: `-987654321`) فهذا يعني أنك تستخدم مجموعة (Group) — هذا صحيح وسيعمل.

---

### 4. معرفة أرقام فرقك في FPL

افتح [fantasy.premierleague.com](https://fantasy.premierleague.com) → تسجيل الدخول → انظر رابط صفحتك:
```
https://fantasy.premierleague.com/entry/1234567/event/1
                                          ↑
                               هذا هو رقم الفريق (Team ID)
```

كرّر هذه الخطوة لكل فريق تريد متابعته.

### 5. إعداد متغيرات البيئة (محلياً)

```bash
# نسخ ملف المثال

# تعديل القيم الحقيقية
```

> إذا أضفتها، **يجب** أن يتطابق عددها مع عدد الـ IDs وإلا ستُرمى رسالة خطأ واضحة.

> [!CAUTION]
> **لا ترفع ملف `.env` للـ GitHub أبداً!** وهو مُضاف بالفعل لـ `.gitignore` حمايةً لبياناتك.

## GitHub Actions (التشغيل التلقائي اليومي)

### كيف يعمل النظام الجديد

بدلاً من الجدولة على يوم ثابت (جمعة)، النظام يعمل **يومياً** ويتحقق من الديدلاين:

```
كل يوم 12:00 UTC:
  ├── جلب bootstrap-static
  ├── استخراج deadline_time للجولة القادمة
  ├── حساب الفرق الزمني (UTC)
  │
  ├── إذا تبقّى > 24 ساعة  → توقف فوري (exit 0) — لا إرسال، لا معالجة
  ├── إذا تبقّى ≤ 24 ساعة  → تابع التحليل
  │
  ├── تحقق من last_sent_gw.json
  ├── إذا نفس الجولة أُرسلت مسبقاً → توقف (لا تكرار)
  └── إرسال التقارير + حفظ last_sent_gw
```

### إضافة الأسرار لـ GitHub

اذهب إلى: **Repo → Settings → Secrets and variables → Actions → New repository secret**

أضف هذه الأسرار:

| الاسم | القيمة | ملاحظة |
|---|---|---|
| `FPL_TEAM_IDS` | `1234567,7654321` | أرقام الفرق مفصولة بفاصلة |
| `FPL_TEAM_NAMES` | `فريق محمد,فريق علي` | اختياري — أسماء للتقارير |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من @BotFather | إلزامي |
| `TELEGRAM_CHAT_ID` | معرّف محادثتك مع البوت | إلزامي |

> [!WARNING]
> `FPL_TEAM_ID` (المفرد) لم يعد مدعوماً — استخدم `FPL_TEAM_IDS` (الجمع) حتى لو كان فريقاً واحداً.

### الجدولة التلقائية

يعمل تلقائياً **كل يوم الساعة 12:00 UTC** — سيُرسل التقرير فقط في اليوم/الأيام التي يكون فيها الديدلاين خلال 24 ساعة.

> [!NOTE]
> **لا حاجة لتعديل الـ cron يدوياً بعد الآن.** النظام يقرأ الديدلاين الفعلي من FPL API مباشرة.
> لو الديدلاين تغيّر (بسبب مباراة مؤجلة مثلاً)، النظام يتكيف تلقائياً.

### تشغيل يدوي للاختبار

**Actions → FPL Weekly Report → Run workflow → Run workflow**

## القيود والمبادئ الأساسية

- ❌ **لا تنفيذ تلقائي داخل حساب FPL** — القراءة والتوصية فقط
- ❌ **لا مفاتيح API مدفوعة** — كل شيء مجاني
- ❌ **لا AI API خارجي** — منطق قواعد (rules-based) بالكامل
- ✅ **كل الأسرار من متغيرات بيئة فقط** — لا توجد بيانات حساسة بالكود
- ✅ **كل التوصيات كـ"اقتراح للمراجعة"** — ليست أوامر نهائية
- ✅ **معالجة الأخطاء الصريحة** — فشل فريق واحد لا يوقف الباقي
- ✅ **عزل كامل بين الفرق** — ملفات حالة وأرشيف منفصلة لكل فريق
- ✅ **جدولة ذكية** — فحص يومي للديدلاين الفعلي، بدون تكرار إرسال

## استكشاف الأخطاء

**مشكلة: رسالة خطأ `FPL_TEAM_IDS مفقود`**
→ تحقق من ملف `.env` — استخدم `FPL_TEAM_IDS` (بدون `FPL_TEAM_ID` القديم)

**مشكلة: `FPL_TEAM_NAMES يحوي X اسم بينما FPL_TEAM_IDS يحوي Y رقم`**
→ عدد الأسماء يجب أن يتطابق تماماً مع عدد الـ IDs — مثال: `FPL_TEAM_IDS=1,2` يحتاج `FPL_TEAM_NAMES=اسم أ,اسم ب`

**مشكلة: رسالة خطأ `Unauthorized` من تيليجرام**
→ `TELEGRAM_BOT_TOKEN` خاطئ — تحقق من القيمة الكاملة بما فيها النقطتين `:` والرقم قبلها

**مشكلة: لا توجد نتائج في الجولة 1**
→ طبيعي — قبل بدء الموسم الفعلي، بعض endpoints لا تُرجع بيانات (get_my_team، الترتيب)

**مشكلة: GitHub Actions ينجح لكن لا تصل رسالة**
→ تحقق من `TELEGRAM_CHAT_ID` — تأكد أنك أرسلت رسالة للبوت أولاً قبل استخراج الـ ID

**مشكلة: تقرير فريق واحد وصل والثاني لم يصل**
→ تحقق من سجلات Actions — فشل أحد الفرق يُرسل إشعار خطأ خاص به ثم يكمل للفريق التالي

**مشكلة: لا يُرسل أي تقرير رغم قُرب الديدلاين**
→ تحقق من سجلات Actions — إذا ظهر "لم يحن وقت الإرسال بعد" فهذا طبيعي.
   إذا الديدلاين أقل من 24 ساعة ولا يزال لا يُرسل، تحقق من `data/state/last_sent_gw.json`
   — ربما تحتاج لحذفه يدوياً (أو تعديله) لو أردت إعادة الإرسال.

**مشكلة: يُرسل التقرير مرتين لنفس الجولة**
→ مستحيل بالتصميم — `last_sent_gw.json` يمنع التكرار.
   إذا حصل، تحقق أن خطوة commit في workflow تعمل بشكل صحيح.
