# 05 - top_managers.py

## الهدف من هذا الملف
جلب تشكيلات أفضل N مدير عالمياً (افتراضياً 10) ومقارنتها بتشكيلة المستخدم، لإنتاج إشارات "إجماع الخبراء" — **يبدأ العمل فقط بعد انتهاء الجولة الأولى فعلياً** (قبل ذلك، `squad_optimizer.py` هو المستخدَم بدلاً منه).

## الارتباط بباقي الملفات
- يستخدم `fpl_client.get_league_standings()` لجلب قائمة أفضل المدراء.
- يستخدم `fpl_client.get_my_team()` (بمعرّف كل مدير) لجلب تشكيلتهم.
- مخرجاته تُغذّي `decision_engine.py` كأحد مصدرين رئيسيين للقرار (المصدر الآخر هو `injuries_source.py`).

## خطوات التنفيذ التفصيلية

### 1. `get_top_n_manager_ids(n=10)`
يستدعي `get_league_standings(league_id=314)` ويستخرج أول N قيمة `entry` من قائمة `results`.

**تحذير مهم:** هذا الـ endpoint يتحدّث بترتيبه **بعد انتهاء كل جولة**، فيجب استدعاؤه بعد إغلاق الجولة، لا أثناءها (تحقق من `bootstrap-static → events → finished == true` للجولة الحالية قبل الاعتماد على الترتيب).

### 2. `get_top_n_squads(manager_ids, gameweek)`
لكل `manager_id`، استدعِ `get_my_team(manager_id, gameweek)` واجمع النتائج بقائمة من التشكيلات (15 لاعب لكل واحد).

**ملاحظة أداء:** هذا يعني N طلب HTTP (مثلاً 10 طلبات). أضف تأخير بسيط بين الطلبات (مثال: نصف ثانية) لتفادي أي حظر مؤقت من FPL API بسبب كثرة الطلبات المتتالية.

### 3. `calculate_consensus(top_n_squads)`
يبني قاموساً: لكل `player_id`، كم عدد المدراء (من أصل N) يملكونه؟
```json
{"player_id_123": 9, "player_id_456": 2, ...}
```

### 4. `compare_my_team_with_consensus(my_squad, consensus_data, total_top_n)`
**الدالة الأساسية التي يستدعيها `decision_engine.py`.** تُصنّف كل لاعب بتشكيلتي إلى:
- **`players_not_in_top_n`**: لاعب عندي، تكراره بالإجماع = 0. (إشارة قوية، لكن ليست حكماً نهائياً — راجع الملاحظة أدناه).
- **`players_low_presence`**: تكراره 1-2 من أصل N.
- **`players_high_consensus_missing`**: لاعب **لا أملكه**، لكن تكراره ≥ 70% من N (مثال: 7+ من 10) — إشارة أنه ربما يستحق الدخول لتشكيلتي.

## ⚠️ القاعدة المنهجية الأهم بهذا الملف
غياب لاعب من تشكيلات أفضل N **لا يعني تلقائياً أنه لن يلعب أساسياً بناديه**. قد يكون فقط:
- غير مفضَّل استراتيجياً (سعره مرتفع مقابل بدائل أرخص).
- المدراء الكبار مركّزين على مركز آخر بنفس الميزانية.
- تفضيل شخصي وليس معلومة موضوعية عن التشكيلة الفعلية.

**لذلك:** هذا الملف **لا يقرر التحويل بنفسه أبداً**. مخرجاته تُمرَّر فقط لـ `decision_engine.py` الذي يدمجها إلزامياً مع بيانات `injuries_source.py` قبل أي توصية — ويُعرض أي غياب غير مؤكد بالإصابة كـ`flagged_players` (للمراجعة اليدوية) وليس كتحويل مقترح مباشر.

## معايير القبول
- [ ] `get_top_n_manager_ids()` يُرجع فعلياً أفضل N مدير عالمياً (تحقق يدوياً بمقارنة الأسماء بموقع FPL الرسمي).
- [ ] `calculate_consensus()` يعطي أرقاماً منطقية (لا يتجاوز أي تكرار قيمة N).
- [ ] الدالة تتعامل مع فشل جلب تشكيلة مدير واحد من أصل N دون إيقاف الباقي (استمر بالباقين، سجّل تحذير للفاشل فقط).
- [ ] لا يوجد أي منطق هنا يتخذ قرار تحويل نهائي — فقط بيانات مقارنة خام.
