# 04 - injuries_source.py

## الهدف من هذا الملف
تحديد حالة كل لاعب (سليم / مشكوك بلعبه / مصاب / موقوف) من مصدر مصنّف جاهز، **بدون تحليل نصوص حرة أو تصريحات** (تم استبعاد هذا حسب قرار المستخدم — الاعتماد فقط على مصادر مصنّفة رقمياً).

## الارتباط بباقي الملفات
- `decision_engine.py` يستدعي هذا الملف كخطوة أولى قبل أي قرار تحويل — أي لاعب "مصاب/موقوف" له أولوية قصوى بالاستبدال.
- `top_managers.py` **لا يتقاطع مباشرة** مع هذا الملف، لكن `decision_engine.py` يدمج مخرجات الاثنين معاً (راجع قاعدة الدمج بملف `07_decision_engine.md`).

## مصدرين للبيانات (بالترتيب من الأكثر موثوقية)

### المصدر الأساسي (يُفضَّل دائماً): حقل من FPL API نفسه
داخل `bootstrap-static` → `elements`، كل لاعب فيه:
- `chance_of_playing_next_round`: قيمة من (0, 25, 50, 75, 100) أو `null` إذا لا توجد شكوك حول لياقته.
- `news`: نص قصير رسمي من FPL نفسه (مثال: "Knee injury - Expected back 15 Sep") — **هذا نص رسمي مختصر من FPL مباشرة، وليس scraping، لذلك موثوق وثابت البنية**.
- `status`: حرف يوضح الحالة (`a`=available, `d`=doubtful, `i`=injured, `s`=suspended, `u`=unavailable).

**هذا المصدر يُفضَّل دائماً كأساس لأنه رسمي ومستقر (endpoint واحد لا يتغير بنيوياً).**

### المصدر الثانوي (اختياري، لمزيد من التفاصيل): موقع إصابات مصنّف خارجي
`BeautifulSoup4` لصفحة جدول إصابات جاهزة (مثال: Premier Injuries) **فقط لإضافة تفاصيل إضافية** (مثل تاريخ توقّع العودة) — وليس كمصدر أساسي لأن بنية المواقع الخارجية تتغير وتحتاج صيانة.

## خطوات التنفيذ

### 1. `get_injury_status_from_fpl(bootstrap_data)`
يبني قاموساً: `{player_id: {"status": "d", "chance": 75, "news": "..."}}` مباشرة من بيانات `bootstrap-static` (لا حاجة لطلب HTTP إضافي — البيانات موجودة أصلاً من `fpl_client`).

### 2. `get_injury_status_from_external_source(url)` (طبقة إضافية اختيارية)
- طلب HTTP لصفحة المصدر الخارجي.
- تحليل الجدول بـ `BeautifulSoup4`.
- **معالجة فشل إلزامية:** لو تغيّرت بنية الموقع أو فشل الطلب، لا يجب أن يوقف هذا البرنامج بالكامل — يُسجَّل تحذير واضح ويُكتفى بالمصدر الأساسي (FPL نفسه) فقط.

### 3. `merge_injury_data(fpl_data, external_data)`
يدمج المصدرين مع إعطاء الأولوية دائماً لبيانات FPL الرسمية عند التعارض.

## تصنيف الحالة النهائي المُستخدم بباقي المشروع
```json
{
  "player_id": 123,
  "status": "doubtful",   // "fit" | "doubtful" | "injured" | "suspended"
  "chance_of_playing": 75,
  "note": "Knee injury - Expected back 15 Sep"
}
```

## معايير القبول
- [ ] كل لاعب بالتشكيلة له حالة واضحة (لا يوجد لاعب بدون تصنيف — الافتراضي `"fit"` إذا لا توجد بيانات مقلقة).
- [ ] فشل المصدر الخارجي لا يوقف تشغيل باقي المشروع.
- [ ] بيانات FPL الرسمية دائماً لها الأولوية عند أي تعارض.
