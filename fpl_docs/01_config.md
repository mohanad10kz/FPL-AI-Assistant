# 01 - config.py

## الهدف من هذا الملف
نقطة مركزية واحدة لقراءة كل الإعدادات والأسرار. **لا يوجد ملف آخر بالمشروع يقرأ متغيرات بيئة مباشرة** — الكل يستورد من هنا. هذا يمنع تكرار الكود ويسهّل تتبع أي إعداد ناقص من مكان واحد.

## الارتباط بباقي الملفات
كل ملف تقريباً (`fpl_client`, `injuries_source`, `telegram_notifier`, `main`) يستورد `config.py` أولاً قبل أي شيء آخر. هو **الجذر** الذي تعتمد عليه كل الوحدات.

## خطوات التنفيذ التفصيلية

### 1. تعريف كلاس أو كائن إعدادات واحد
لا تستخدم متغيرات متفرقة — اجمعها بكلاس واحد (مثال: `Config`) بحيث الاستيراد بباقي الملفات نظيف: `from config import config`.

### 2. المتغيرات المطلوبة وتحقق كل واحد منها
| المتغير | إلزامي؟ | تحقق مطلوب |
|---|---|---|
| `FPL_TEAM_ID` | نعم | رقمي، وليس فارغ |
| `TELEGRAM_BOT_TOKEN` | نعم | يطابق الصيغة `<digits>:<string>` |
| `TELEGRAM_CHAT_ID` | نعم | رقمي (قد يكون سالب لو مجموعة) |
| `INJURY_SOURCE_URL` | لا (له قيمة افتراضية) | رابط صحيح |
| `TOP_N_MANAGERS` | لا (افتراضي = 10) | رقم صحيح موجب |

### 3. رمي خطأ واضح عند نقص إعداد إلزامي
عند التشغيل، إذا `FPL_TEAM_ID` غير موجود مثلاً، يجب أن يتوقف البرنامج فوراً برسالة خطأ صريحة بالعربية أو الإنجليزية توضح بالضبط أي متغير ناقص — **وليس** خطأ عام غامض (`KeyError` بدون سياق). هذا مهم لأن التشغيل يكون عبر GitHub Actions بدون تدخل بشري مباشر، فلازم السجل (logs) يوضح المشكلة فوراً.

### 4. ملف `.env.example`
أنشئ ملف بنفس أسماء المتغيرات لكن بدون قيم حقيقية، ليكون مرجعاً لأي شخص يشغّل المشروع محلياً:
```
FPL_TEAM_ID=your_team_id_here
TELEGRAM_BOT_TOKEN=your_bot_token_here
TELEGRAM_CHAT_ID=your_chat_id_here
INJURY_SOURCE_URL=https://example.com/injuries
TOP_N_MANAGERS=10
```

### 5. القراءة المحلية مقابل GitHub Actions
- محلياً: استخدام مكتبة `python-dotenv` لقراءة ملف `.env` (والذي يجب أن يكون بـ `.gitignore` ولا يُرفع أبداً).
- على GitHub Actions: القيم تأتي من GitHub Secrets وتُمرَّر كمتغيرات بيئة بالـ workflow مباشرة (لا حاجة لملف `.env` هناك).
